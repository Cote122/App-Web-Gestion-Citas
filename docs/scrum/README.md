# Preparación de Scrum en GitHub

Este directorio es el punto de partida para pasar el Product Backlog al repositorio.

## Propuesta de trabajo

- Crear un **GitHub Project** con columnas `Product Backlog`, `Ready`, `Sprint`, `In Progress`, `Review`, `Done`.
- Crear un Issue por HU y, si es necesario, subtareas técnicas.
- Etiquetas recomendadas: `HU`, `frontend`, `backend`, `database`, `security`, `bug`, `tech-debt`, `Sprint-1` ... `Sprint-4`.
- Estimar Story Points únicamente después del refinamiento del equipo.
- Vincular cada Pull Request con el Issue correspondiente (`Closes #NN`).

## Definition of Ready antes de mover una HU a Sprint

- Historia y valor entendibles.
- MoSCoW definido.
- Criterios de aceptación comprobables.
- Dependencias identificadas.
- Estimada por Developers.

## Definition of Done sugerida para el repositorio

- Código integrado en la rama objetivo.
- Criterios de aceptación validados.
- Pruebas funcionales/técnicas superadas.
- Sin defectos críticos conocidos.
- Roles/permisos respetados.
- Sin datos clínicos reales.
- Documentación mínima actualizada.
- Pull Request revisado por otro integrante.
